# Project verification

- Project name is `Last Day` (was "Un dia mas"). `project.godot` pins `config/use_custom_user_dir` + per-platform `custom_user_dir_name` overrides so `user://` still resolves to the legacy `app_userdata/Un dia mas` directory — saves and `stop_server.flag` paths are unchanged. The custom-dir base is bare (`~/.local/share/` on Linux, `~/Library/Application Support/` on macOS, `%APPDATA%` on Windows) — no `godot/app_userdata` prefix is added — so each override carries the full legacy tail (`godot/app_userdata/Un dia mas` on Linux, `Godot/app_userdata/Un dia mas` on macOS/Windows). Verify with `lsof`/`proc` on a live process, not just by checking the dir exists.

When moving a const out of a script, also check `tools/debug` and regression scripts that reach it via instance (`world.X`) or inheritance.
- Run isolated SceneTree regression scripts using `--headless --path . --script /absolute/path/to/test.gd`; use a nonzero exit code on failed assertions. Override world initialization and saving in test doubles to avoid generating the full map or writing player saves.

The output is `build/macos/LastDay.app`; do not delete the existing app before exporting. - Dedicated server exports (all `dedicated_server=true`, auto-start on UDP 5005 game / 5006 LAN discovery; `NetworkManager` detects `OS.has_feature("dedicated_server")`): `"macOS Server"` → `build/macos/LastDayServer.app`, `"Windows Server"` → `build/windows/LastDayServer.exe` + `.pck`, `"Linux Server"` → `build/linux/LastDayServer.x86_64` (embedded pck). The `build/linux` and `build/windows` dirs must exist before exporting.
- Server shutdown paths (all delete `server_savegame.json` — the world is per-session and never survives a close): macOS — Dock > Salir on the launcher app; Linux — type `quit` + Enter in its terminal or run `stop_server.sh`; Windows — type `quit` + Enter in its console or run `stop_server.bat`. The flag lives in `user://stop_server.flag` and carries the PID(s) to stop (one per line — written by `stop_server.sh`, `start_server.sh` and the macOS launcher; an empty flag is a kill-all). The server only honors a flag naming its own PID, leaves flags for other processes untouched, and cleans up flags older than 30 s — a fresh boot must never eat a stop request meant for a server that is still shutting down. If `create_server` fails (port still held), the dedicated process retries ~10 s then exits instead of running a networkless world (`~/Library/Application Support/Godot/app_userdata/Un dia mas` on macOS, `~/.local/share/godot/app_userdata/Un dia mas` on Linux, `%APPDATA%\Godot\app_userdata\Un dia mas` on Windows). `pkill`/`kill`/closing the console window skip the save — avoid.
- After exporting `macOS Server`, run `tools/make_server_launcher.sh`: it turns `LastDayServer.app` into a stay-open AppleScript launcher containing the real server at `Contents/Resources/LastDayServerCore.app`. This is required because headless dedicated_server builds never receive `NOTIFICATION_WM_CLOSE_REQUEST` (Godot's `applicationShouldTerminate` only forwards it when a real window exists), so Dock > Salir/Cmd+Q silently do nothing on the raw export. The launcher catches the quit event, touches `user://stop_server.flag`, and the server deletes `server_savegame.json` and exits.
- To update an already wrapped macOS server without rebuilding/deleting its launcher, export `"macOS Server" "build/macos/LastDayServer.app/Contents/Resources/LastDayServerCore.app"`, restore `LSUIElement=true` in the core's `Contents/Info.plist`, then run `codesign --force --deep --sign - build/macos/LastDayServer.app` and `codesign --verify --deep --strict build/macos/LastDayServer.app`.
- `tools/start_server.sh` prefers the launcher app (`open`) on macOS and `build/linux/LastDayServer.x86_64` on Linux, then falls back to the raw exported binary / `Godot --headless --server`. The server console also accepts `status`/`players` and `save` on stdin. Plain `kill`/`pkill` skips the flag cleanup but the world is wiped on next boot anyway; the 60-second autosave only matters inside a session.
- Deploys ALWAYS wipe the server world: never write `keep_world.flag` or preserve `server_savegame.json` when deploying — restart plain so `Main._ready` deletes the save and generates a fresh world. The flag mechanism only exists for the rare case the user explicitly asks to keep the session.
- Dedicated-server world is per-session: `Main._ready` deletes `server_savegame.json` (+ `.bak`) before world load, so every boot is a fresh world — drops, open doors, depleted loot and player records do NOT persist across restarts. Within a session, reconnects still restore state from the in-memory `_server_saved_players` baseline and the 60s autosave; the autosave file only matters for the client-side saved-server card preview. Exception: `user://keep_world.flag` skips the delete in BOTH `Main._ready` (consumes the flag, single boot) and `_request_server_shutdown` (leaves it for the boot to consume) — place it before a restart to carry the current world over a deploy.
- A join in flight (peer created, handshake pending/failed) must still count as multiplayer: `join_game` leaves `is_connected=false` until the handshake, so save/load guards check `net.is_connected or net.peer != null` (SaveGameHooks) and `Main._ready` sets `_mp_session` on `net.peer != null`. Never gate single-player save paths on `is_connected` alone. `NetworkManager._on_connection_failed`/`_on_server_disconnected` call `close_connection` so a dead peer never leaks into later single-player sessions, and `Inicio._start_game` refuses to enter the world while a `join` is still unconnected.

# Project verification

- Local Godot executable: `work/godot4.7/Godot.app/Contents/MacOS/Godot` (Godot 4.7).
- Parse check: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --check-only --script scripts/Main.gd`. Read the output: this executable can exit with status 0 even when it reports a script parse error.
- Run isolated SceneTree regression scripts using `--headless --path . --script /absolute/path/to/test.gd`; use a nonzero exit code on failed assertions. Override world initialization and saving in test doubles to avoid generating the full map or writing player saves.
- Export macOS with `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --export-release "macOS"`. The output is `build/macos/LastDay.app`; do not delete the existing app before exporting.
- Dedicated server exports (all `dedicated_server=true`, auto-start on UDP 5005 game / 5006 LAN discovery; `NetworkManager` detects `OS.has_feature("dedicated_server")`): `"macOS Server"` → `build/macos/LastDayServer.app`, `"Windows Server"` → `build/windows/LastDayServer.exe` + `.pck`, `"Linux Server"` → `build/linux/LastDayServer.x86_64` (embedded pck). The `build/linux` and `build/windows` dirs must exist before exporting.
- Server shutdown paths (all save `server_savegame.json` first): macOS — Dock > Salir on the launcher app; Linux — type `quit` + Enter in its terminal or run `stop_server.sh`; Windows — type `quit` + Enter in its console or run `stop_server.bat`. The flag lives in `user://stop_server.flag` (`~/Library/Application Support/Godot/app_userdata/Un dia mas` on macOS, `~/.local/share/godot/app_userdata/Un dia mas` on Linux, `%APPDATA%\Godot\app_userdata\Un dia mas` on Windows). `pkill`/`kill`/closing the console window skip the save — avoid.
- After exporting `macOS Server`, run `tools/make_server_launcher.sh`: it turns `LastDayServer.app` into a stay-open AppleScript launcher containing the real server at `Contents/Resources/LastDayServerCore.app`. This is required because headless dedicated_server builds never receive `NOTIFICATION_WM_CLOSE_REQUEST` (Godot's `applicationShouldTerminate` only forwards it when a real window exists), so Dock > Salir/Cmd+Q silently do nothing on the raw export. The launcher catches the quit event, touches `user://stop_server.flag`, and the server saves `server_savegame.json` and exits.
- To update an already wrapped macOS server without rebuilding/deleting its launcher, export `"macOS Server" "build/macos/LastDayServer.app/Contents/Resources/LastDayServerCore.app"`, restore `LSUIElement=true` in the core's `Contents/Info.plist`, then run `codesign --force --deep --sign - build/macos/LastDayServer.app` and `codesign --verify --deep --strict build/macos/LastDayServer.app`.
- `tools/start_server.sh` prefers the launcher app (`open`) on macOS and `build/linux/LastDayServer.x86_64` on Linux, then falls back to the raw exported binary / `Godot --headless --server`. The server console also accepts `status`/`players` and `save` on stdin. Plain `kill`/`pkill` loses everything since the last 60-second autosave.
- Dedicated-server world is per-session: `Main._ready` deletes `server_savegame.json` (+ `.bak`) before world load, so every boot is a fresh world — drops, open doors, depleted loot and player records do NOT persist across restarts. Within a session, reconnects still restore state from the in-memory `_server_saved_players` baseline and the 60s autosave; the autosave file only matters for the client-side saved-server card preview.
- A join in flight (peer created, handshake pending/failed) must still count as multiplayer: `join_game` leaves `is_connected=false` until the handshake, so save/load guards check `net.is_connected or net.peer != null` (SaveGameHooks) and `Main._ready` sets `_mp_session` on `net.peer != null`. Never gate single-player save paths on `is_connected` alone. `NetworkManager._on_connection_failed`/`_on_server_disconnected` call `close_connection` so a dead peer never leaks into later single-player sessions, and `Inicio._start_game` refuses to enter the world while a `join` is still unconnected.
- Inventory restore regression: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/debug/BackItemsSaveRegression.gd`. Uses isolated players/world without save writes; covers direct/buffered network restores, repeated restores, clothing/backpack capacity, item payload preservation and zero dropped-item signals. Also covers duplicate loot notifications, complete pickup removal before saving, stale snapshots, and depletion received during map generation. Network equipment restoration must hold `_initializing` until all equipment is restored, then refresh capacity. Changes to `_apply_restored_inventory` require reexporting the client, not just the dedicated server.
- Main owns the live HUD reference (`hud`). It creates the CanvasLayer dynamically without naming it `HUD`; UI shortcuts should use that reference rather than a hard-coded node path.
- After externally reexporting GLB assets, run Godot with `--headless --path . --import` before testing; running a script alone can load stale imported scenes.
- Wolf navigation regression: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/debug/WolfRiverRegression.gd`. Checks reachable river detours, safe shore escape, retreat from disconnected/elevated/no-route player targets, cooldown before renewed pursuit, and door updates without generating the world or writing saves.
- Navigation performance: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/debug/NavigationPerformanceRegression.gd`. Run without other heavy tests for meaningful timing. It covers real river geometry, unreachable goals, door connectivity and query budgets; append `-- --baseline` to reproduce the previous exhaustive search (expected budget failures).
- Saved-position regression: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/debug/SavePositionRegression.gd`. Uses an isolated player without loading or writing save files; normal loads must preserve the saved position. Lake teleport testing requires a debug build with the explicit `--debug-lake-spawn` user argument.
- Rowboat regression: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script scripts/RowboatRegression.gd`. For a moving-water-effects capture, omit `--headless` and append `-- --preview`; it saves `/tmp/lastday_rowboat_preview.png` without generating the map or saving player data.
- Forest regression: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script scripts/ForestRegression.gd`. For a visual capture, omit `--headless` and append `-- --preview`; it saves `/tmp/lastday_forest_preview.png` without generating the full map.
- Village regression: `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --script scripts/VillageRegression.gd`. For a visual capture, omit `--headless` and append `-- --preview`; it saves `/tmp/lastday_village_preview.png` without generating the full map or writing player saves. Append `-- --preview --gallery` to capture all ten house variants to `/tmp/lastday_house_*.png`. Add `--views` to save four-sided eye-level contact sheets (`*_views.png`). It checks wall vegetation orientation, clearance around all six windows and the doorway, facade bounds, the 0.85 m moss-height limit, per-house variety, and closed roofs with outward clockwise winding, flat normals and separate gable/roof materials.
- Blender village textures: `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python tools/blender/generate_village_textures.py -- --size 1024`. Use `--size 2048 --only lime,ochre,stone,brick` for the detailed facade maps; the bake combines Blender procedural wear with existing plaster/concrete source textures. It renders `assets/textures/overgrowth/village_*_{albedo,normal,roughness,height}.png`; run `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --import` afterwards.
- Blender shore assets: `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python tools/blender/generate_shore_assets.py`. Renders `assets/textures/shore/shore_band_{albedo,normal,roughness,height}.png` (wet→mud→sand strip used by `_create_shore_band`) and exports `assets/models/props/shore/shore_{driftwood,flatstone,pebbles}_*.glb`; run `work/godot4.7/Godot.app/Contents/MacOS/Godot --headless --path . --import` afterwards.
- Blender riverbank modules: `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python tools/blender/create_reference_riverbanks.py`. Exports `riverbank_reference_{0,1,2}.glb` (six-metre cobble+grass bank modules, local +Z away from water, origin at waterline) plus `shore_reference_{albedo,normal}.png` (real ganges-pebble strip + disp-derived normal used by `_create_shore_band`). `scripts/RiverbankDetails.gd` tiles the modules as MultiMeshes along river/lake edges with per-segment RNG (does NOT touch `_world_rng`), gap skips and yaw jitter; it runs client-side only via `_create_river_segment`. Blender `image.pixels` is bottom-up, so band array index 0 lands on the PNG bottom row = mesh v=1 (land edge). Visual check: `work/godot4.7/Godot.app/Contents/MacOS/Godot --path . --script tools/debug/ShorePreview.gd` (needs a window — do NOT use `--headless`); saves `/tmp/lastday_shore_preview.png`. GLB prop meshes get `MaterialFactory.make_forest_rock_material(tint)` overrides for grain; the pebble patch GLB must stay flat (bake transforms before `join()` or it exports upright).
